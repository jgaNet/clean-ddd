# Working on this repository (guide for AI assistance)

This is the **Python implementation** of the Clean Architecture + Domain-Driven Design reference. The rules themselves, and what every language of the reference shares, are in the root [CLAUDE.md](../CLAUDE.md); this guide is Python's: its commands, where its things are, how a feature is added here. Before changing anything, read the [README](README.md): it says what is written so far, how the decisions land in Python, and maps every concept to the file that shows it. The TypeScript guide ([`typescript/CLAUDE.md`](../typescript/CLAUDE.md)) is the fuller one: the shape of a feature is the same, and the questions it answers under [*Questions you will have*](../typescript/CLAUDE.md#how-to-add-a-feature-follow-an-existing-one-do-not-invent-a-shape) — which verb, where a test goes, whether an event needs a handler, what an archived thing refuses — are answered the same way here; read that list before guessing.

Every command below runs from this directory (`cd python`), after `uv sync` once.

## Commands

```bash
uv run python -m tools.conventions          # every import is the table, the tree matches the binding, every named file exists
uv run python -m tools.conventions inventory          # what the tree says the application is, as canonical JSON (ARCH-ONE-APPLICATION)
uv run python -m tools.conventions inventory --write  # writes it to docs/inventory/python.json, which the check holds current
uv run ruff format --check .                # the formatter (uv run ruff format . to apply)
uv run ruff check .                         # the lints
uv run mypy                                 # strict typing, src/ and tools/
uv run pytest                               # every test_*.py; uv run pytest src/contexts/notes for one context, -k <name> for one test
node ../api/scenario.mjs http://127.0.0.1:10000   # the API every language answers, against a running server (uv run python -m bootstrap)
yarn --cwd .. architecture rule <ID> | concept <id> | checklist <kind> | verb <intent>   # the contract, asked; from here it answers in Python (`--language python` says it explicitly)
                                            # the kinds: aggregate, value-object, domain-service, command, query, integration-event, event-handler, context
uv run python -m tools.conventions can-import <file> <module> [<file> <module> …]   # would this import be allowed? names the rule that refuses it
yarn --cwd .. architecture mode feature --base <ref>   # did this change leave the architecture alone (`--base working` for uncommitted changes; the default base is origin/main)
yarn --cwd .. conventions:write  # re-render README.md after editing conventions/python.yaml
```

All five checks must pass before a change is done; CI runs them on every PR, from this directory.

## Where things are

```
src/architecture/<layer>/         the building blocks, one package per layer: domain (Entity, AggregateRoot, ValueObject, Id,
                                  the three kinds of Event, DomainException, Result), application (the base handlers,
                                  ExecutionContext, Operation, the EventBus port, Module), infrastructure (the in-memory pieces)
src/shared_kernel/<layer>/        domain (Email, Role), application (require_signed_in, integration_events/)
src/contexts/<context>/           one package per layer (domain/, application/, infrastructure/, presentation/) and the
                                  wiring file module_local.py beside them
  domain/<aggregate>/<aggregate>.py   the aggregate; beside it <name>.py value objects, events.py, <aggregate>_exceptions.py,
                                  dtos.py (the snapshot), <rule>.py domain services, ports/, and test_<x>.py for each
  application/commands/<use_case>.py  the command and its handler; queries/<use_case>.py a query handler;
                                  events/<fact>_handler.py a reaction; test_commands.py beside the commands
  infrastructure/<ports>.py       repositories.py, queries.py, suggestions.py: the adapters; test_persistence_contract.py
  presentation/routes.py          the routes and their views, one APIRouter per context; presenters.py beside it
src/bootstrap/                    the composition root (create_application.py) on the transport (fastapi_application.py, no
                                  context), the settings, the entry point (__main__.py), testing.py and the end-to-end
                                  suites test_*_e2e.py
  starter/                        the composition root `create` gives a new application: the Tracker alone (ADR 27)
tools/conventions.py              the import linter and conventions check, in one
../conventions/python.yaml        this language's binding of the contract: contexts, trees, enforcers, checklists, canonical files
```

**A module is imported by its absolute path** (`from contexts.notes.domain.note.note import Note`), never by a relative path across directories (`from ..note import Note`): the import linter matches on the absolute path, and a relative import may only name a sibling module (ARCH-RELATIVE). A tree is a top-level package under `src/`: `architecture`, `shared_kernel`, `contexts.<context>`, `bootstrap`; a layer is the contract's name in lowercase.

## The rules (enforced)

The rules are the contract's, the same in every language, and listed in the root [CLAUDE.md](../CLAUDE.md). What is Python's is in [`conventions/python.yaml`](../conventions/python.yaml), this language's **binding**: the contexts, the trees, the libraries only an adapter may import, which tool holds each rule here (`tools/conventions.py` for the dependency table and the tree, strict `mypy`, a `test_*.py`, review), what a new thing of each kind is made of (`yarn --cwd .. architecture checklist <kind>`), and the file that shows each concept and each rule.

- **The architecture is data.** A new context goes in `contexts` of the binding, with one package per layer; a new file worth pointing at goes under `concepts` of the binding; a new rule goes in the contract, and in no binding. Neither is edited to make a violation pass.

## How to add a feature (follow an existing one, do not invent a shape)

Ask the contract first: `yarn --cwd .. architecture checklist <kind>` lists what a new one is made of in Python and where it goes, with the placeholders filled in snake_case (typed from this directory it answers in Python; `--language python` says it explicitly). A plan is optional: `plan validate|explain` works on one that says `language: python` ([`conventions/plans/share-a-note.rust.yaml`](../conventions/plans/share-a-note.rust.yaml) is the example of a plan written for one language; a Python one is `conventions/plans/<feature>.python.yaml`, `crossContext` only when the feature crosses one), and is worth writing when a feature crosses a context or raises a modelling question.

1. **Domain first.** Add a behaviour to the aggregate that enforces the rule and records an event ([`note.py`](src/contexts/notes/domain/note/note.py)): check the rules with the private `_ensure_*` helpers (return their `Failure` as is), change the state, `self._record(SomethingHappenedEvent(...))`, return `OK`. A pure read skips the aggregate: its first step is a read model and a method on the queries port ([`note_queries.py`](src/contexts/notes/domain/note/ports/note_queries.py)). New concept with validation? A value object ([`note_title.py`](src/contexts/notes/domain/note/note_title.py)): a frozen dataclass extending `ValueObject[T]`, `create()` returning a `Result`, one exception per rule the user could act on differently in [`note_exceptions.py`](src/contexts/notes/domain/note/note_exceptions.py) (a `DomainException` subclass with a PascalCase `type`); a behaviour an archived note refuses reuses `_ensure_active()` and its `NoteArchived`, since the remedy is the same (restore first). New rule about the whole collection, or a fact another context owns? A domain service taking its port in `__init__` ([`note_sharing.py`](src/contexts/notes/domain/note/note_sharing.py)). A new fact is a new frozen dataclass in [`events.py`](src/contexts/notes/domain/note/events.py), extending `DomainEvent`, named in the past tense, its fields the payload. A behaviour that needs a **new attribute** (`_pinned`) adds it to `__slots__`, to the private constructor, to `create()` with its default, to `from_snapshot()` / `to_snapshot()` and to the snapshot in [`dtos.py`](src/contexts/notes/domain/note/dtos.py) (a default there keeps the existing literals of the tests valid), and exposes it through a property; the snapshot round-trip test tells you if you forgot one. An act undone (restore, unpin) is not gated by `_ensure_active()`, like `restore()`: an owner can always tidy up. Tests in `test_<aggregate>.py` beside it.
2. **Command + handler**, in one file copied from [`edit_note.py`](src/contexts/notes/application/commands/edit_note.py): the command, a frozen dataclass extending `CommandEvent` with its fields the payload, and the handler, a class extending `CommandHandler[TheCommand]` taking its ports in `__init__`, with `execute()` — `require_signed_in(context, SERVICE)` → load → ask the aggregate → `save()` → `self.publish_domain_events(note, context)` → `OK`; every step that can refuse returns its `Failure` as is. Or a query handler from [`get_note.py`](src/contexts/notes/application/queries/get_note.py): `QueryHandler[NoteQueries, <parameters>, <read model>]`, `execute()` reads the port and nothing else. The tests of the handlers of one aggregate share the fixture of [`test_commands.py`](src/contexts/notes/application/commands/test_commands.py): the in-memory repository is the double, and its `RecordingBus` says what was published; every command handler has at least its happy path and one refusal there, through `execute()` (a rule in a `guard()` override is tested through `handle()`, with an `Operation(command, context)` built by hand).
3. **Infrastructure** only if a port changed. A new adapter of an existing port is one more entry in `adapters` of [`test_persistence_contract.py`](src/contexts/notes/infrastructure/test_persistence_contract.py) and must pass it unchanged; that is the whole review — the SQLite pair in [`repositories.py`](src/contexts/notes/infrastructure/repositories.py) and [`queries.py`](src/contexts/notes/infrastructure/queries.py) got in that way, over the table of [`notes_table.py`](src/contexts/notes/infrastructure/notes_table.py). A new column is a line in the table, a field in `to_row()` / `to_snapshot()`, a column in the `UPDATE` and the `INSERT` of `SqliteNoteRepository.save()`, and a field in every read model the SQLite queries build; the contract test's round-trip case tells you if you forgot one, provided it exercises the new field. A new read-model field is a field on the dataclass in `note_queries.py`, built by both adapters, and a camelCase key in the view function of the routes: FastAPI serialises whatever the view returns, so there is no schema to forget, and nothing to list for a field to appear.
4. **Route + controller** in the context's [`presentation/routes.py`](src/contexts/notes/presentation/routes.py): an `async def` per route on the context's `APIRouter`, taking the `Request` and, for a body, a pydantic model declared beside the route. A command is `accept(context_of(request), TheCommand(...))` — the `202` goes out, the dispatch runs after; a query is `module.get_query(TheHandler).handle(..., context)`, answered through a view function (camelCase keys: what the API promises) or refused through the file's `refuse_*()`, which maps the context's own kinds before `status_of()`. An answer the HTMX front end also wants is a `ByFormat` of two presenters, picked by `format_of(request.headers)` ([`security/presentation/presenters.py`](src/contexts/security/presentation/presenters.py)); JSON is mandatory, HTMX optional. The verb follows the HTTP grammar (`yarn --cwd .. architecture verbs`): `POST /notes` creates, `PUT /notes/{id}` replaces, `POST /notes/{id}/share` acts; an action undone is a second act named after the undoing (`/archive` and `/restore`), never a `DELETE`. The HTMX front end is the presenters' example, not a second client to keep in parity: a new command does not oblige a new form control. Prove it end to end in [`src/bootstrap/test_<context>_routes_e2e.py`](src/bootstrap/test_notes_routes_e2e.py): follow a `202` with `app.accepted(client, response)`, which polls the operation to its outcome; each case boots its own application with `start_test_application()`. The end-to-end suite and the shared scenario ([`api/scenario.mjs`](../api/scenario.mjs)) assert the exact shape of every response, field count included: a feature that changes what a client sees (a new field, a new route) fails the scenario against this server until the other languages carry it, which is the point of [ADR 16](../docs/adr/0016-one-api-for-every-language.md); the feature is done in its language when its end-to-end suite proves it, and the scenario is then the list of what the other languages owe.
5. **List it in the wiring** ([`module_local.py`](src/contexts/notes/module_local.py)): `Subscription(TheCommand, [TheHandler(ports)])` under `commands`, the handler instance under `queries`, `Subscription(TheFact, [TheReaction()])` under `domain_events`.
6. Cross-context reaction? Publish an integration event from a domain event handler ([`notes/.../note_shared_handler.py`](src/contexts/notes/application/events/note_shared_handler.py)): the contract is a frozen dataclass extending `IntegrationEvent` in the shared kernel's [`integration_events/`](src/shared_kernel/application/integration_events/note_integration_events.py), in the publishing context's public words. The consuming context reacts with an anti-corruption handler in its own `events/` ([`notifications/.../note_shared_handler.py`](src/contexts/notifications/application/events/note_shared_handler.py)): it knows the contract and nothing else of the other context, restates the fact in its own words, and calls its own use case; listed in its wiring under `integration_events`, on the contract's class.
7. **The map.** A new file worth pointing at goes under `concepts` in [`conventions/python.yaml`](../conventions/python.yaml); then `yarn --cwd .. conventions:write` and `uv run python -m tools.conventions`. A second use of a kind the map already shows (another command on an aggregate) is not a new example: the map stays as it is, and a feature does not edit the binding.

## Questions you will have, in Python words

The TypeScript list linked above is the full one; these are the answers a Python reader reaches for most, in this language's vocabulary.

- **Does every domain event need a handler?** No. The aggregate records the fact because it happened (`NoteEditedEvent` has no handler); subscribe one in `module_local.py` only when something reacts. An integration event exists only once a first consumer needs the fact.
- **Does the read side's order matter?** Yes, and it belongs to the queries port: the order a method returns is in its docstring ([`note_queries.py`](src/contexts/notes/domain/note/ports/note_queries.py)) and asserted for every adapter by the contract test. A query handler never sorts; an adapter does (a stable `sorted()` in memory, an `ORDER BY` in SQL).
- **Does a new exception need a line in `refuse_*()`?** No. It maps *kinds* (`NotAllowedException` → 403, the aggregate's not-found exception → 404, anything else → 400); a refused command never reaches it, it is on the operation.
- **Which HTTP verb?** `yarn --cwd .. architecture verb <intent>`: `GET` for a query, `POST` to create and for an action on a thing, `PUT` to replace, `PATCH` for a partial state change, `DELETE` for a thing truly gone. A toggle is two acts (`/pin` and `/unpin`), never a `DELETE`.
- **Where does the test go?** Beside what it tests, as `test_<x>.py`: the aggregate's in `test_note.py`, the handlers of one aggregate in `test_commands.py`, one case per adapter in the contract test, the user-visible flow in `src/bootstrap/test_<context>_routes_e2e.py`. A rule in a `guard()` override is tested through `handle()` with an `Operation` built by hand.
- **How do I compare things in a test?** A value object, an event, a snapshot and a read model are frozen dataclasses: `==` compares every field. An aggregate keeps its state private: compare with `equals()` (the same thing?) or through `to_snapshot()` (the same state?). A `Result` compares as a dataclass too; narrow it with `isinstance(result, Failure)` and read `result.error.type`.
- **An existing event needs more data for a new consumer?** Widen the frozen dataclass in `events.py` and the `_record()` call in the behaviour, which holds the state; do not add a second event for the same fact. One fact is one message: a fact with several interested parties is one event carrying the list (`shared_with`), and the fan-out is the consumer's business. The contract names it in Notes' public words (`recipient_ids`), and is published whenever the fact happens, the list empty or not.
- **Do event handlers need a guard?** No. A domain or integration event handler reacts to a fact that was already allowed, in the publisher's context; the base `EventHandler` has no `guard()`. An anti-corruption handler that fans out calls the local use case once per recipient, returns the first `Failure` as is, and answers `Success` with what it created.
- **Barrels?** None. An import names the module (`from contexts.notes.application.commands.pin_note import PinNoteCommandEvent`); a package's `__init__.py` holds a docstring and nothing else, except the two of the building blocks that re-export their Domain and Application.

## Code style

- Python ≥ 3.13; `ruff format` applied, `ruff check` clean (the rules in `pyproject.toml`), `mypy --strict` clean.
- Private attributes everywhere in the domain (`self._title`), reached through properties; the only way into an aggregate is `create()` or `from_snapshot()`, the only way into a value object is `create()`. Accessors return copies of lists, never the list.
- `Result[T]` in every signature that can refuse; a `Failure` is returned as is; `raise` only for corrupted state, with the id in the message. No `assert` outside tests as a check of business state.
- A handler takes its ports in `__init__`, shared with the other handlers of the aggregate; the only state it holds is those ports (ARCH-EXECUTION-CONTEXT: a clock, a mailer, a model client is such a port, never a member of the context).
- An event's channel is its class name, read with `name_of(event)` or `name_of(TheEvent)`; a payload field may be called `name`. A handler publishes with `context.event_bus.publish(event, context)` and never awaits it: the dispatch is a task, and a test that wants to see it awaits the in-memory bus's `settle()`.
- A port is a `Protocol`; an adapter implements it without naming it, and so does a test double (`class Directory:` with one `async def exists`). Keep `Any` out of the use cases: the base handlers are the one place the bus is type-erased.
- A route never builds a handler, an adapter or a context: it gets its `Module` from the composition root and the request's context from `context_of(request)`. A library (`fastapi`, `starlette`, `pydantic`, `httpx`, `bcrypt`, `jwt`, `uvicorn`) appears in a `presentation/` or `infrastructure/` package, in the bootstrap, or in an end-to-end test, and the import linter refuses it anywhere else.
- A blocking call (bcrypt) runs in a thread (`asyncio.to_thread`); a handler publishes and never awaits the dispatch.
- `snake_case` modules named after what they hold (`note_title.py`, `note_sharing.py`); `PascalCase` classes; an exception's `type` in PascalCase (`NotNoteOwner`); an enum's value is its name (`NoteStatus.ACTIVE == "ACTIVE"`).
- A docstring at the top of a module explains *why* the file exists and what rule it protects, in a few lines. No commented-out code, no `print()` outside `tools/` (the lint refuses it).
- Conventional commits (`feat:`, `fix:`, `refactor:`, `chore:`, `docs:`), one concern per PR, and the PR body states how it was verified.

## Things to avoid

- A relative import across directories, or an import of another context's internals: `tools/conventions.py` says no and names the rule; the fix is a port, an integration event or a move — never an edit to the binding.
- A rule in `conventions/python.yaml`: a binding points at files and holds no rule (ARCH-ONE-CONTRACT).
- A `Result` class of our own with methods that hide the `Failure`, a `Mapper`, a generic `Repository[T]`, a service locator or a DI container.
- Raising a `DomainException`: it does not extend `BaseException`, on purpose; a refusal is returned.
- A mutable dataclass for a value object or an event: they are `frozen=True`, and that is the immutability.
