# Vague requests: four of J5's features in product words only

The side experiment of the [J5 kit](../../README.md): requests 53, 68, 79 and 98 written a second time with their rules in product words only, as a product owner would hand them over: the thresholds, patterns, windows and exceptions of the precise request are left out. Each keeps its API table (routes and fields), since the hidden tests call it. Each runs on a copy of every tree, from the same commit as the ladder's attempt at the precise request, with the same ladder, and is graded by the same hidden tests.

- **The Clean DDD arm** gets the feature's storm session again, on the vague request: its open questions are answered by the maintainer before the run, and the answers count as that arm's cost.
- **The simple arm** cannot ask anyone: it decides alone, as a developer handed a vague ticket would.

A guess that differs from the precise request fails the hidden tests, in either arm; the measures are the escalations, the amendments the vague requests needed, and the cost.

**Decided by the maintainer on 2026-11-04.** The proposal said no route, body or status. The kit found that a request without its API cannot pass the hidden tests, which call its routes, so the simple arm would fail by construction. The maintainer decided that the rules are vague and the API is given.
