# LLM multi-agent systems for code generation and software development, and the simple-pipeline / single-agent alternatives that challenge them

Scope note: notes compiled 2026-10-30 for the related-work section of a study comparing one LLM coding agent (arm A, with a gate and expected event storms) against architecture-coordinated fan-outs (C, C′: storm, per-context plans, frozen integration events, acceptance test, single-writer integration) and naive parallel fan-out (B) on a 7-feature TypeScript Clean Architecture + DDD backlog. Unless stated, figures were read on the arXiv HTML/abstract page cited. "Abstract only" is flagged where the full text was not read.

## Q1. Agentless (Xia et al.): method, SWE-bench Lite results and cost per version, Lite-S, argument against agents

### Takeaway
Agentless replaces an autonomous agent with a fixed three-phase pipeline (hierarchical localization, sampled repair, test-based patch validation and voting) and, with GPT-4o, reached 32.00% on SWE-bench Lite at $0.70/issue (v2), beating every open-source agent of mid-2024 that it compared to, several of them at 2–4x its cost. It is the canonical "simple pipeline beats agents" result and the closest methodological ancestor of our claim that a fixed, gated single-agent process can dominate more elaborate coordination.

### Cited Findings
- Bibliography: Chunqiu Steven Xia, Yinlin Deng, Soren Dunn, Lingming Zhang (UIUC). arXiv 2407.01489, v1 1 Jul 2024, v2 29 Oct 2024; the arXiv page carries no venue comment. — [arXiv abs v1](https://arxiv.org/abs/2407.01489v1)
- Peer-reviewed version: "Demystifying LLM-Based Software Engineering Agents", Proceedings of the ACM on Software Engineering (FSE 2025), DOI 10.1145/3715754, published 2025-06-19, presented 25 Jun 2025, Trondheim. — [FSE 2025 program](https://conf.researchr.org/details/fse-2025/fse-2025-research-papers/85/Demystifying-LLM-based-Software-Engineering-Agents) (venue/DOI via search result summary of the program page)
- Argument against agents — three named limitations: (1) complex tool usage/design: abstraction layers and API call formats are error-prone and wasted turns add cost; (2) lack of control in decision planning: agents can take 30–40 turns, making decisions hard to understand and debug; (3) limited self-reflection: agents accept irrelevant or misleading feedback, so one wrong step is amplified. Framing question: "Do we really have to employ complex autonomous software agents?" — [arXiv HTML v2](https://arxiv.org/html/2407.01489)
- Method, localization (hierarchical): repo shown as a tree, LLM ranks top-N suspicious files; in parallel, embedding retrieval (text-embedding-3-small, chunk 512, overlap 0, LlamaIndex) after an LLM pass filters irrelevant folders; files found by both are kept; default top-3 files. Files compressed to a "skeleton" of class/function headers, LLM selects relevant elements; then full code of those elements, LLM outputs edit locations; 4 samples of edit locations per issue. — [arXiv HTML v2](https://arxiv.org/html/2407.01489)
- Method, repair: ±10 lines of context per location set; Search/Replace diff format; 10 patches per location set (1 greedy + 9 at T=0.8) = 40 candidate patches per issue. — [arXiv HTML v2](https://arxiv.org/html/2407.01489)
- Method, validation: 40 candidate reproduction tests generated (1 greedy + 39 sampled), kept only if they print "Issue reproduced" on the original repo, normalized, most frequent selected; existing regression tests run (LLM removes those the fix may legitimately change); patches with fewest regression failures kept, then must pass the reproduction test (fallback to regression only); finally AST-normalized and ranked by majority vote. — [arXiv HTML v2](https://arxiv.org/html/2407.01489)
- Setup: GPT-4o (gpt-4o-2024-05-13); SWE-bench Lite (300 issues); metrics: % resolved, average $ cost, average tokens, % correct location (line/function/file). No repeated runs or variance reported. — [arXiv HTML v2](https://arxiv.org/html/2407.01489)
- Results v1 (Jul 2024): 27.33% on SWE-bench Lite at $0.34 per issue ("highest performance (27.33%) and lowest cost ($0.34)" among open-source approaches). — [arXiv abs v1](https://arxiv.org/abs/2407.01489v1)
- Results v2 (Oct 2024): 96/300 (32.00%), avg $0.70, avg 78,166 tokens; correct location 35.3% line, 52.0% function, 69.7% file. Closed-source CodeStory Aide reported 129 (43.00%). — [arXiv HTML v2](https://arxiv.org/html/2407.01489)
- Comparison table (v2, SWE-bench Lite): SWE-agent (Claude 3.5 Sonnet) 69 (23.00%) $1.62; SWE-agent (GPT-4o) 55 (18.33%) $2.53; AutoCodeRover (GPT-4) 57 (19.00%) $0.45; AutoCodeRover-v2 (GPT-4o) 92 (30.67%) cost n/r; OpenDevin+CodeAct v1.8 (Claude 3.5 S) 80 (26.67%) $1.14; Aider 79 (26.33%) n/r; Moatless (Claude 3.5 S) 80 (26.67%) $0.17; SpecRover 93 (31.00%) $0.65; CodeR (GPT-4, a multi-agent system) 85 (28.33%) $3.34; RAG baseline (Claude 3 Opus) 13 (4.33%) $0.25. — [arXiv HTML v2](https://arxiv.org/html/2407.01489)
- Ablations: patch selection by majority vote alone 77 (25.67%); + regression tests 81 (27.00%); + reproduction tests 96 (32.00%). Repair: greedy location 88 (29.33%), merged samples 85 (28.33%), multi-sample locations 96 (32.00%); 126 (42.0%) issues solvable if any sampled patch counted (oracle selection). — [arXiv HTML v2](https://arxiv.org/html/2407.01489)
- SWE-bench Lite-S: authors manually classified the 300 problems and removed those with the exact ground-truth patch in the description (4.3% of 300), misleading solutions in the description (5.0%), or insufficient information (10.0%) — 51 removed, 249 kept (categories may overlap). Agentless resolves 84/249 (33.73%), ranked 9th; CodeStory Aide leads with 114 (45.78%). Agentless does well on issues with reproducible examples; closed-source agents do better when no location clue is given. — [arXiv HTML v2](https://arxiv.org/html/2407.01489)
- SWE-bench Verified: 194/500 (38.80%) with GPT-4o; best listed was a closed-source "Tools" entry (Claude 3.5 Sonnet 20241022) at 245 (49.00%). — [arXiv HTML v2](https://arxiv.org/html/2407.01489)
- Adoption claim (authors'): "already been adopted by OpenAI as the go-to approach to showcase the real-world coding performance of GPT-4o", also used for the o1 family; OpenAI ran it on Lite, full and Verified. Not independently verified here. — [arXiv HTML v2](https://arxiv.org/html/2407.01489)
- Authors' own limitations: possible data leakage of SWE-bench patches into GPT-4o; generalization tested mainly on SWE-bench Lite; only 213/300 issues yield a test that reproduces the bug, and only 94 of those pass with the ground-truth patch. — [arXiv HTML v2](https://arxiv.org/html/2407.01489)

### Inferences
- Agentless is a precedent for our arm A in spirit: control flow is fixed by the harness (localize → repair → validate), not decided by the model; our "gate + expected storm" similarly fixes the shape of the work while one agent writes it. Its ablation shows most of the gain came from validation (reproduction tests +15 issues), which parallels our acceptance tests and gate.
- Agentless reports cost per issue alongside accuracy, which most multi-agent papers (ChatDev, MetaGPT on HumanEval) do not; our study's cost-and-time reporting follows the Agentless convention.
- Agentless and SWE-bench are issue-level repair in an existing repo; none of these numbers say anything about greenfield multi-feature construction, integration across modules, or architecture conformance — our setting.
- Single run, no variance: same weakness as our pilot (one run per arm); worth saying explicitly.

### Gaps
- The final ~25k characters of the v2 HTML (discussion/threats) were not read; FSE camera-ready numbers may differ slightly from arXiv v2 (not checked against the ACM PDF).
- Exact per-category removal counts for Lite-S are not given in the text read.

## Q2. Multi-agent code-generation / software-development systems: coordination and evaluation

### Takeaway
The well-known multi-agent systems coordinate by role-play (ChatDev: chat chain of role pairs; MetaGPT: SOP assembly line with structured documents and publish-subscribe; Self-collaboration: analyst/coder/tester; AgentCoder: programmer/test designer/executor; MapCoder: retrieval/plan/code/debug; MAGIS: manager/custodian/developer/QA). They were evaluated either on isolated functions (HumanEval, MBPP, APPS, CodeContests) or on small single-prompt "apps" (SRDD, SoftwareDev) scored by executability or embedding similarity, or on single-issue repair (SWE-bench). None of those read measures integration of several features into one codebase, architecture conformance, or compares to a single strong agent at equal token/dollar budget; the baselines are a single LLM call or other multi-agent frameworks. Notably, ChatDev and MetaGPT each report beating the other on their own benchmark.

### Cited Findings
**ChatDev** (Qian et al., ACL 2024; arXiv 2307.07924 v1 16 Jul 2023, v5 5 Jun 2024)
- Coordination: a "chat chain" of phases — design (natural language), coding (writing, completion), testing (code review as static testing, system testing as dynamic) — 5 subtasks across 3 phases, each a dialogue between two role agents (CEO, CTO, programmer, reviewer, tester). "Communicative dehallucination": the assistant requests more specific details before answering; used in completion, review and testing. — [arXiv HTML v5](https://arxiv.org/html/2307.07924v5); venue from [arXiv abs](https://arxiv.org/abs/2307.07924)
- Evaluation: SRDD, 1,200 one-line software requirement prompts in 5 areas (Education, Work, Life, Game, Creation), 40 subcategories × 30. Metrics: completeness (% without placeholder code), executability (% that compile and run), consistency (cosine similarity of requirement and code embeddings), quality = product of the three. ChatGPT-3.5, T=0.2; GPT-4 as pairwise evaluator. Number of runs not stated; no monetary cost reported (limitations note more tokens/time for multi-agent). — [arXiv HTML v5](https://arxiv.org/html/2307.07924v5)
- Results (Table 1): GPT-Engineer completeness 0.5022 / executability 0.3583 / consistency 0.7887 / quality 0.1419; MetaGPT 0.4834 / 0.4145 / 0.7601 / 0.1523; ChatDev 0.5600 / 0.8800 / 0.8021 / 0.3953 (significance p ≤ 0.05 marked). Pairwise wins (baseline/ChatDev/draw): vs GPT-Engineer, GPT-4 judge 22.50/77.08/0.42, human 9.18/90.16/0.66; vs MetaGPT, GPT-4 judge 37.50/57.08/5.42, human 7.92/88.00/4.08. Table 3 statistics: duration 15.6 s (GPT-Engineer), 154.0 s (MetaGPT), 148.2 s (ChatDev); tokens 7,183 / 29,279 / 22,949; files 3.95 / 4.42 / 4.39; lines 70 / 153 / 144. — [arXiv HTML v5](https://arxiv.org/html/2307.07924v5)

**MetaGPT** (Hong et al., ICLR 2024 oral; arXiv 2308.00352)
- Venue: ICLR 2024, oral. — [ICLR virtual page](https://www.iclr.cc/virtual/2024/oral/19756); [ICLR proceedings](https://proceedings.iclr.cc/paper_files/paper/2024/hash/6507b115562bb0a305f1958ccc87355a-Abstract-Conference.html)
- Coordination: five roles (Product Manager, Architect, Project Manager, Engineer, QA Engineer) in a sequential SOP-driven assembly line; agents exchange structured artifacts (PRD, system design, interface definitions) instead of free chat; shared message pool with publish-subscribe so each role sees only what is relevant; executable feedback — the Engineer runs unit tests and debugs, max 3 retries. — [arXiv HTML](https://arxiv.org/html/2308.00352)
- Evaluation: HumanEval Pass@1 85.9%, MBPP 87.7% (executable feedback adds +4.2 / +5.4 points). SoftwareDev: 70 tasks, 7 randomly selected for the main comparison; metrics: executability (1–4 scale), running time, tokens, cost, code statistics, productivity (tokens per line), human revision cost. — [arXiv HTML](https://arxiv.org/html/2308.00352)
- Results vs ChatDev on SoftwareDev: executability 3.75 vs 2.25; tokens 31,255 vs 19,292; productivity 124.3 vs 248.9 tokens/line; human revision cost 0.83 vs 2.5; running time 541 s vs 762 s in the table (text cites 503 s, the w/o-feedback value — an internal inconsistency). — [arXiv HTML](https://arxiv.org/html/2308.00352)
- Role ablation: Engineer only — executability 1.0, 10 revisions, $0.915; Engineer + PM + Architect + Project Manager — executability 4.0, 2.5 revisions, $1.385. — [arXiv HTML](https://arxiv.org/html/2308.00352)

**Self-collaboration code generation** (Dong, Jiang, Jin, Li; arXiv 2304.07590, v3 11 May 2024; "Accepted to TOSEM")
- Roles analyst, coder, tester following a development methodology, as a "virtual team" of ChatGPT instances. Reports a relative Pass@1 improvement of 29.9%–47.1% over the base single LLM agent on code-generation benchmarks; claims (without numbers on the abstract page) it can handle repository-level tasks. Abstract only. — [arXiv abs](https://arxiv.org/abs/2304.07590)

**AgentCoder** (Huang, Zhang, Luck, Bu, Qing, Cui; arXiv 2312.13010, v3 24 May 2024; no venue on the arXiv page)
- Programmer agent, test designer agent, test executor agent; feedback loop. GPT-4: HumanEval 96.3%, MBPP 91.8% vs previous SOTA 90.2% / 78.9%; token overhead 56.9K (HumanEval) and 66.3K (MBPP) vs 138.2K / 206.5K for the SOTA baseline; 9 models, 12 enhancement approaches. Abstract only. — [arXiv abs](https://arxiv.org/abs/2312.13010)

**MapCoder** (Islam, Ali, Parvez; ACL 2024 long, pp. 4912–4944)
- Four agents mirroring the program-synthesis cycle: example retrieval, planning, coding, debugging. Pass@1: HumanEval 93.9%, MBPP 83.1%, APPS 22.0%, CodeContests 28.5%, xCodeEval 45.3%; compared to Reflexion, AlphaCodium. Abstract only. — [arXiv abs](https://arxiv.org/abs/2405.11403); venue [ACL Anthology](https://aclanthology.org/2024.acl-long.269.pdf)

**AgentVerse** (Chen et al.; arXiv 2308.10848, v3 23 Oct 2023)
- Abstract: a multi-agent framework that "can collaboratively and dynamically adjust its composition"; claims groups "outperform a single agent"; no numbers on the abstract page; page said "Under review". Abstract only. — [arXiv abs](https://arxiv.org/abs/2308.10848)

**CodeAgent** (Zhang, Li, Li, Shi, Jin; ACL 2024 main per arXiv comment)
- Repo-level code generation with five integrated tools (retrieval, symbol navigation, testing) and four agent strategies; CodeAgentBench = 5 Python projects, 101 samples; improves 9 LLMs by ~18.1%–250%; claims to beat GitHub Copilot. The abstract does not say it is multi-agent — it is a tool-integrated agent framework, better cited as a single-agent-with-tools system. Abstract only. — [arXiv abs](https://arxiv.org/abs/2401.07339)

**MAGIS** (NeurIPS 2024; arXiv 2403.17927)
- Four agents (Manager, Repository Custodian, Developer, Quality Assurance) for GitHub issue resolution. 13.94% on full SWE-bench (claimed eight-fold over GPT-4 direct), 8.71% without QA and hints; 25.33% on SWE-bench Lite vs AutoCodeRover 16.11% (mean of 3 runs) and SWE-agent 18.00%. Read via search summary of the paper, not the NeurIPS PDF tables. — [NeurIPS 2024 PDF](https://proceedings.neurips.cc/paper_files/paper/2024/file/5d1f02132ef51602adf07000ca5b6138-Paper-Conference.pdf); [arXiv](https://arxiv.org/pdf/2403.17927)
- For comparison, Agentless v2 (single pipeline, GPT-4o) reached 32.00% on the same Lite benchmark; the multi-agent CodeR reached 28.33% at $3.34/issue vs Agentless $0.70. — [Agentless arXiv HTML](https://arxiv.org/html/2407.01489)

**Industry positions (2025), not peer-reviewed**
- Anthropic's multi-agent research system (Claude Opus 4 lead + Sonnet 4 subagents) outperformed single-agent Opus 4 by 90.2% on an internal research eval; agents use ~4x the tokens of chat, multi-agent systems ~15x; token usage alone explains 80% of performance variance on BrowseComp; the post says most coding tasks have fewer truly parallelizable subtasks than research and agents are not yet good at real-time coordination and delegation. Published 13 Jun 2025. — [Anthropic engineering blog](https://www.anthropic.com/engineering/multi-agent-research-system)
- Cognition (Walden Yan, "Don't Build Multi-Agents", 12 Jun 2025): principles "Share context, and share full agent traces, not just individual messages" and "Actions carry implicit decisions, and conflicting decisions carry bad results"; Flappy Bird example — one subagent builds a Super-Mario-style background, another a bird matching neither style nor movement; recommends a single-threaded linear agent, with a context-compression model for long tasks. — [Cognition blog](https://cognition.com/blog/dont-build-multi-agents)

### Inferences
- The coordination mechanisms of MetaGPT (structured documents, interface definitions handed between roles) are the closest prior to our contract stage (storm, per-context plans, frozen integration events). The difference: MetaGPT divides by role/phase (pipeline), while our C/C′ divide by bounded context (parallel fan-out) and hold the result to a checked architecture. I found no system that partitions work by bounded context or module boundary.
- Every multi-agent paper reviewed baselines against a single LLM call or other multi-agent frameworks, not a single agent with the same tools, tests and budget. MetaGPT's role ablation is the nearest thing ("Engineer only" got executability 1.0) but the single Engineer had no planning or tests — it is a straw single agent compared to our arm A.
- The ChatDev-vs-MetaGPT reversal (each wins on its own benchmark and metric) is a useful caution: self-reported comparisons between frameworks are not reliable evidence.
- Cognition's "conflicting implicit decisions" is the informal mechanism behind our arm B's merge conflicts in one context; our arm C's frozen contracts and single-writer integration are an attempt to make those decisions explicit before fan-out — and the pilot suggests that the cost of doing so outweighed the parallelism gained, consistent with Anthropic's remark that coding tasks are less parallelizable.

### Gaps
- AgentVerse: venue (believed ICLR 2024) and its coding results (HumanEval, "Solo" baseline) were not verified; only the abstract was read.
- AgentCoder's peer-reviewed venue (if any) not found.
- Newer (2025–2026) "AI software company" systems (ChatDev successors such as MacNet / co-learning, AgileCoder, OpenHands multi-agent delegation, SWE-agent variants) were not researched in depth for lack of budget; no verified numbers here.
- I found no system in this set that measures architecture conformance (layering, dependency rules) or integration of several features into one codebase.

## Q3. Independent evaluations and critiques (numbers)

### Takeaway
Independent studies consistently find that multi-agent organisation adds overhead without commensurate gains on coding tasks: a 7-framework comparison with a fixed backend (DeepSeek-v3.1) found the two multi-agent frameworks among the worst on SRDD software development and far behind on SWE-bench Lite (3–10% vs 47–54%), at the highest cost; MAST found 41–86.7% failure rates across seven open-source MAS including ChatDev and MetaGPT; a 2026 ICSME paper found a single-agent README pipeline matches multi-agent lexical quality with 86% fewer tokens; a Chalmers thesis found a hierarchical supervisor pattern worst (54.4% vs 81.1% single agent) while a sequential pipeline was best (92.2%); Google/MIT found multi-agent variants degrade sequential tasks by up to 70%.

### Cited Findings
**Yin et al., "A Comprehensive Empirical Evaluation of Agent Frameworks on Code-centric Software Engineering Tasks"** (arXiv 2511.00872, 2 Nov 2025, preprint; authors Zhuowen Yin, Cuifeng Gao, Chunsong Fan, Wenzhang Yang, Yinxing Xue, Lijun Zhang)
- Seven general-purpose frameworks: multi-agent AgentOrchestra, OWL; single-agent SE-Agent (3 iterations), Trae, GPTswarm, OpenHands, SWE-Agent (paper notes OpenHands has a delegation mechanism). Tasks: software development on SRDD (1,200 prompts), vulnerability detection on LLM-SmartAudit (115 contracts), program repair on SWE-bench Lite (300). All on DeepSeek-v3.1, 100-step limit; number of runs not stated. — [arXiv HTML](https://arxiv.org/html/2511.00872); [arXiv abs](https://arxiv.org/abs/2511.00872)
- Software development (quality score): OpenHands 0.47, SE-Agent iter-1 0.46, GPTswarm 0.45, Trae 0.40, SWE-Agent 0.39, AgentOrchestra 0.36, OWL 0.36 (SE-Agent iter-2 0.22, iter-3 0.15). — [arXiv HTML](https://arxiv.org/html/2511.00872)
- Program repair (resolved /300): SE-Agent iter-3 161 (54%), SWE-Agent 159 (53%), Trae 154 (51%), OpenHands 146 (49%), OWL 31 (10%), GPTswarm 15 (5%), AgentOrchestra 10 (3%). Vulnerability detection: SWE-Agent 87/115 (76%) best, AgentOrchestra 51 (44%) worst (text/table inconsistency for GPTswarm noted). — [arXiv HTML](https://arxiv.org/html/2511.00872)
- Cost (sum of per-task columns of Table 10, as read by the fetch tool; the paper's own "Total" row appears misaligned): AgentOrchestra $370.19 (highest), OpenHands $115.37, SWE-Agent $73.22, Trae $66.34, OWL $25.43, GPTswarm $16.29 (lowest). Software development was the costliest task ($544.90 across frameworks). Average steps on software development: AgentOrchestra 40.2, OpenHands 81.3, SWE-Agent 27.4, GPTswarm 7.0. — [arXiv HTML](https://arxiv.org/html/2511.00872)
- Conclusion stated in the paper: multi-agent systems have "substantially longer average steps"; "the proliferation of agents in multi-agent system introduces substantial interaction overhead" (planner ↔ specialist agents, information overload); "single-agent system consistently demonstrates superior performance compared to multi-agent system" on these tasks; MAS also had more correction attempts. — [arXiv HTML](https://arxiv.org/html/2511.00872)

**Cemri et al., "Why Do Multi-Agent LLM Systems Fail?" (MAST)** (UC Berkeley; arXiv 2503.13657, v3 26 Oct 2025)
- Seven MAS: MetaGPT, ChatDev, HyperAgent, AppWorld, AG2 (MathChat), Magentic-One, OpenManus. Taxonomy built from 150 traces (κ = 0.88), 14 failure modes in 3 categories; MAST-Data = 1,642 annotated traces. Failure rates 41% to 86.7% across the open-source MAS. — [arXiv HTML v3](https://arxiv.org/html/2503.13657v3); [search summary of project page](https://sky.cs.berkeley.edu/project/mast/)
- Category shares (summed by the fetch tool from per-mode figures): system design issues ~44.2% (largest modes FM-1.3 15.7%, FM-1.1 11.8%), inter-agent misalignment ~32.4% (FM-2.6 13.2%), task verification ~23.5%. — [arXiv HTML v3](https://arxiv.org/html/2503.13657v3)
- ProgramDev: 30 simple coding problems (Tic-Tac-Toe, Chess, Sudoku…); v2 has 100. ChatDev correctness on ProgramDev reported as 33.33% on the project page, and "as low as 25%" in the v1 preprint (versions differ). Interventions on ChatDev (GPT-4o): better role specifications +9.4% success; a high-level task-objective verification step +15.6% (v1 reported +14%); authors conclude simple fixes are insufficient. — [arXiv HTML v3](https://arxiv.org/html/2503.13657v3); [search summary of MAST site](https://sky.cs.berkeley.edu/project/mast/)
- Paper states MAS gains "often remain minimal compared to single-agent frameworks" and simple baselines like best-of-N, citing prior work (no own numbers). — [arXiv HTML v3](https://arxiv.org/html/2503.13657v3)

**Saleh et al., "The Illusion of Agentic Complexity in README.md Generation: Evaluating Single-Agent vs. Multi-Agent RAG Systems"** (ICSME 2026, NIER/Visions track; arXiv 2606.30524, v1 29 Jun 2026, v2 1 Jul 2026; Saleh, Tesfay, Nguyen, Di Rocco, Zeshan, Di Ruscio)
- Compares single-agent RAG pipeline, a specialised multi-agent system, and developer-guided planning (DevPlan), against LARCH and original READMEs. Single agent "achieves lexical quality comparable to MAS while reducing token consumption by 86%", ~2x faster; MAS reaches 98% structural consistency and fixes formatting issues; autonomous planning identified as the main bottleneck; DevPlan gives the highest overall quality. Abstract only (no per-metric numbers, dataset size not stated). — [arXiv abs](https://arxiv.org/abs/2606.30524); [ICSME 2026 program](https://conf.researchr.org/details/icsme-2026/icsme-2026-nier/18/The-Illusion-of-Agentic-Complexity-in-README-md-Generation-Evaluating-Single-Agent-v)

**Agha & Miqdad, "An Empirical Comparison of Multi-Agent LLM Architectural Patterns for Automated Unit Test Generation"** (Chalmers MSc thesis, 2026)
- Review of 31 articles (2023–2026) → taxonomy of 10 coordination patterns. Experiment on TestEval, Claude Sonnet 4, 30 tasks per architecture, 270 executions. Success: single-agent 81.1% ($0.083/task, cheapest), sequential 92.2% (best; lowest latency variance 295.56 s²; $0.089/task), hierarchical 54.4% (worst; highest median latency 142.37 s; $0.308/task mean). Hierarchical failures attributed to a supervisor information bottleneck present in all failing tasks. Authors caution: one model, one benchmark, non-optimised prompts. Abstract page only. — [Chalmers ODR](https://odr.chalmers.se/items/2a008985-ebbd-4cd1-926a-947499da2a66)

**Kim et al., "Towards a Science of Scaling Agent Systems"** (Google Research / DeepMind / MIT; arXiv 2512.08296, v1 9 Dec 2025, v3 8 Apr 2026; no venue listed)
- 260 configurations, 6 agentic benchmarks, 5 architectures (single-agent; independent, centralized, decentralized, hybrid MAS), 3 LLM families, tools/prompts/compute standardized. Relative to single agent: +80.8% on decomposable financial reasoning to −70.0% on sequential planning; diminishing returns once single-agent baselines are strong (capability saturation); tool-heavy tasks incur multi-agent overhead; architectures without centralized verification propagate errors more; predictive model picks the best architecture for 87% of held-out configurations (R² 0.373 / 0.413). — [arXiv abs](https://arxiv.org/abs/2512.08296)
- Secondary figures (blog/v1 summaries, not read in paper): independent MAS amplify errors up to 17.2x, centralized ~4.4x; every MAS variant degraded sequential reasoning by 39–70%; returns turn negative once single-agent baselines exceed ~45%. — [Google Research blog](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/) (via search summary)

### Inferences
- The independent evidence lines up with our pilot: when the backend model is held fixed, multi-agent organisation costs more (Yin et al.: AgentOrchestra ~3x OpenHands' cost) and does not improve quality on software development; our A vs C/C′ (same quality, A faster and ~30% cheaper) is the same pattern on a greenfield, multi-feature, architecture-constrained task, which none of these studies covers.
- The Chalmers result (sequential > single > hierarchical) and the ICSME result (developer-guided plan best) both suggest that what helps is fixed structure decided up front, not autonomous delegation — compatible with our arm A (one agent, but a gate and expected storms) and with Agentless.
- Kim et al.'s "decomposable vs sequential" axis gives a vocabulary for our result: a feature backlog in one codebase looks decomposable by bounded context, but integration (shared kernel, integration events, wiring, merge into one context) reintroduces sequential dependencies — arm B's 3/7 merge failures in one context are a case of the error propagation they describe for independent (uncoordinated) MAS, and arm C's contract stage is a "centralized" fix that contains errors at a coordination cost.
- MAST's largest category (system design / specification issues, ~44%) matches what our contract stage tries to address (frozen contracts, per-context plans); the MAST result that role/verification fixes give only +9–16% suggests the upper bound of such fixes is modest.

### Gaps
- Yin et al.: cost totals derive from the fetch tool's summation of table columns; check Table 10 directly before quoting dollar totals. Number of runs not stated.
- MAST venue (possibly NeurIPS 2025 Datasets & Benchmarks) not confirmed on the pages read.
- ICSME 2026 README paper and Chalmers thesis: only abstracts read; no per-metric tables.
- No independent re-run of ChatDev/MetaGPT on their own SRDD/SoftwareDev benchmarks was found beyond Yin et al. (which re-used SRDD with other frameworks, not ChatDev/MetaGPT) and MAST (ProgramDev).

## Q4. Multi-agent / agent systems building multi-module or full-stack applications from scratch (project-level benchmarks)

### Takeaway
Project-level, from-scratch benchmarks exist (SRDD, SoftwareDev, ProgramDev, DevEval/DevBench, ProjectEval, CodeAgentBench) but they are small (20–70 projects, or one-line prompts) and score executability, similarity or user-simulation tests; absolute scores are low (ProjectEval: GPT-4o Pass@5 ≈12.5%, OpenHands 7.39). None scores architecture conformance or multi-feature integration over a backlog, and none pits a single agent against a coordinated fan-out at equal budget.

### Cited Findings
- **ProjectEval** (Liu, Pan, Xiang, He, Li, Du, Gao; arXiv 2503.07010, v2 31 May 2025; Findings of ACL 2025 per a search summary, not confirmed on the arXiv page): 20 project-level Python tasks (website or console/batch), 284 test cases; three input levels (NL prompt, NL checklist, code skeleton); evaluation by simulated user interaction plus code-similarity indicators. Pass@5 overall: GPT-4o 12.49 (cascade 10.42, direct 13.87; text says "only GPT-4o reach the Pass@5 of 15%"), Gemini 1.5 Pro 6.65, Gemini 2.0 Flash 4.31, GPT-3.5-turbo 2.90; OpenHands (GPT-4o) 7.39; MetaGPT/ChatDev discussed but not evaluated. Code LLMs produced almost no effective results. — [arXiv HTML v2](https://arxiv.org/html/2503.07010v2); [arXiv abs](https://arxiv.org/abs/2503.07010); venue claim via [search results](https://aclanthology.org/people/tianrun-gao)
- **DevBench → DevEval** (Li, Wu, Tang, … Chen Qian, … Kai Chen; arXiv 2403.08604, v3 14 Dec 2024; retitled "Prompting Large Language Models to Tackle the Full Software Development Lifecycle: A Case Study"): stages software design, environment setup, implementation, acceptance testing, unit testing; four languages; authors report current LLMs including GPT-4 "fail to solve the challenges". No venue on the arXiv page. Abstract only; no pass rates read. — [arXiv abs](https://arxiv.org/abs/2403.08604)
- **SoftwareDev** (MetaGPT): 70 tasks, 7 used in the main comparison, executability on a 1–4 scale; MetaGPT 3.75 vs ChatDev 2.25. — [MetaGPT arXiv HTML](https://arxiv.org/html/2308.00352)
- **SRDD** (ChatDev): 1,200 one-line prompts; ChatDev quality 0.3953 vs MetaGPT 0.1523, generated software averaging ~4.4 files and ~144 lines. — [ChatDev arXiv HTML v5](https://arxiv.org/html/2307.07924v5). Re-used by Yin et al. with general frameworks: best quality 0.47 (OpenHands). — [arXiv HTML](https://arxiv.org/html/2511.00872)
- **ProgramDev** (MAST): 30 simple apps/games (v2: 100); ChatDev correctness 25–33% depending on version. — [arXiv HTML v3](https://arxiv.org/html/2503.13657v3)
- **CodeAgentBench**: 5 Python projects, 101 repo-level samples (functions within existing repos, not from scratch). — [arXiv abs](https://arxiv.org/abs/2401.07339)

### Inferences
- The "projects" in these benchmarks are tiny (ChatDev's average ~144 lines in ~4 files) compared to a 7-feature layered DDD backlog with several bounded contexts, an outbox and integration events; claims from them do not transfer to architecture-constrained multi-module work.
- Low absolute scores on ProjectEval (≤15% Pass@5) with a single production agent (OpenHands) show project-level generation was not solved in 2025; our setting differs in that strong 2026 agents complete all 7 features in arms A/C/C′, so the comparison shifts from "can it be done" to "which coordination is cheaper and integrates cleanly".
- Our study's distinctive contributions relative to all of the above: (1) a multi-feature backlog on one evolving codebase, so integration and merge conflicts are measured; (2) architecture conformance checked mechanically (import rules, context map, inventory); (3) a single strong agent with the same tooling as baseline, with time and cost reported per arm.

### Gaps
- DevEval/DevBench numeric results and venue not read (abstract only).
- RepoAgent (documentation generation) and other project-level benchmarks named in the brief (e.g., later 2025–2026 full-stack/app-building benchmarks) not researched within budget; no verified numbers.
- No study was found that measures architecture conformance of multi-agent generated code, or compares single vs multi agent on a multi-feature backlog at equal budget — this absence is itself the gap our study fills, but a broader search (e.g., 2026 ICSE/FSE/ASE proceedings) would be needed to state it with confidence.
