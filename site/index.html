Le projet

Une architecture, quatre langages, zéro convention tacite

Une petite application, lisible

Des notes partagées, des comptes, des notifications, le suivi de chaque opération. Chaque concept DDD et Clean Architecture y apparaît exactement une fois.

Une architecture qui est de la donnée

Les couches, qui importe qui, chaque règle sous un identifiant stable : un contrat YAML dont sont générés le linter et les vérifications. Une frontière qui cède quand ça arrange n’en est pas une.

Quatre langages, une seule API

TypeScript, Rust, Python et Go, chacun avec sa chaîne d’outils. Un même scénario boîte noire passe sur les quatre serveurs ; un même inventaire les tient égaux.

Mesures

Ce que ça coûte, ce que ça apporte

Deux benchmarks ont fait construire la même application par des agents, avec et sans l’architecture, face à des tests cachés. Le résultat est écrit tel quel.

Ça coûte : du temps et de l’argent.

Dans chaque expérience, le projet nu a livré autant, pour 1.4–2.8 fois moins de temps et 3.1–6.0 fois moins cher. Un modèle plus faible n’a pas été aidé non plus.

Ça apporte : une structure qui tient.

Les changements restent dans leur couche, les contextes restent séparés, l’argent n’est pas payé deux fois, et plusieurs agents travaillent sur une même base de code sans conflit.

Un garde-fou et un coordinateur pour les agents, pas un accélérateur. L’article, en anglais, détaille chaque expérience, chaque chiffre lu dans les registres du dépôt.

Concepts

Chaque concept, une fois, au même endroit dans chaque langage

Racine d’agrégat génère son identité, enregistre ses événements, porte sa version.

Objet-valeur valide une fois : create() refuse, fromSnapshot() lève.

Événement de domaine un fait, durable avec l’état, publié après le commit.

Événement d’intégration le contrat entre deux contextes, dans le noyau partagé.

Commande et requête un seul handler par commande ; une requête renvoie un modèle de lecture.

Result, pas exception un refus est une valeur ; lever est réservé aux bugs.

Outbox les événements sont stockés avec l’état et relayés ensuite.

Concurrence optimiste save() refuse un agrégat périmé ; le handler redécide, trois fois.

Ports et adaptateurs tout ce qui n’est pas fonction de l’état métier passe par un port.

Carte des contextes chaque relation déclarée une fois, tenue au code par la vérification.

Politique une réaction à un fait, dans sa propre transaction.

Deux modes une fonctionnalité reste dans l’architecture ; la changer est une décision.

Outillage

L’architecture répond, puis vérifie

Avant d’écrire : demander

Une règle, expliquée

L’énoncé, la raison, la remédiation, le fichier qui la montre.

Un import, jugé

Ce fichier peut-il importer celui-là, et quelle règle le dit.

Une fonctionnalité, décidée

Un event storm facilité, écrit en mots communs aux quatre langages ; une checklist dit quoi écrire et où.

yarn architecture
$ yarn architecture rule ARCH-INWARD
ARCH-INWARD (dependencies-point-inward) — enforced by linter
Dependencies point inward and contexts stay apart — each file
imports only what its row of the dependency table allows;
there is no exception and none may be added.

$ yarn architecture can-import typescript/src/Contexts/Notes/Domain/Note/Note.ts \
    @Contexts/Security/Domain/Account/Account
refused by ARCH-DOMAIN: typescript/src/Contexts/Notes/Domain/Note/Note.ts
may not import '@Contexts/Security/Domain/Account/Account'

$ yarn architecture checklist command --language rust
A new command goes in rust/src/contexts/<context>/application/
  src/commands/<use_case>.rs
Canonical example:
  rust/src/contexts/notes/application/src/commands/edit_note.rs

Après avoir écrit : prouver

Le mode fonctionnalité

Refuse tout changement hors des contextes : briques de base, noyau partagé, conventions, décisions.

La vérification des conventions

Chaque fichier nommé existe, chaque lien résout, chaque sonde d’import se comporte, la carte des contextes est vraie.

Un inventaire, quatre arbres

Chaque langage écrit ce que son arbre dit de l’application ; la vérification en refuse deux qui diffèrent.

les vérifications

Langages

Lancez-la dans le langage que vous lisez le mieux

Même port, même API sous /v1. Le README de chaque langage suit une requête de bout en bout ; son guide dit comment y travailler, à la main ou avec un agent.

TypeScript

Lancer le serveur

cd typescript && yarn install && yarn start:dev

La tenir à l’architecture

yarn check:conventions && yarn lint && yarn test:e2e

Rust

Lancer le serveur

cd rust && cargo run -p bootstrap

La tenir à l’architecture

cargo run -p conventions && cargo clippy && cargo test

Python

Lancer le serveur

cd python && uv sync && uv run python -m bootstrap

La tenir à l’architecture

uv run python -m tools.conventions && uv run pytest

Go

Lancer le serveur

cd go && go run ./bootstrap/cmd/application

La tenir à l’architecture

go run ./tools/conventions && go test ./...
